Fundamentos

¿Qué es una base de datos?

Es un sistema estructurado para almacenar, gestionar y recuperar información. Funciona como la memoria confiable de una aplicación: guarda los datos de forma segura y los entrega en segundos cuando se necesitan.

Imagina una biblioteca digital donde el bibliotecario sabe exactamente en qué página de qué libro está cada dato. Sin ese orden, tendrías millones de hojas sueltas imposibles de consultar.

Los datos

La información en sí: textos, números, fechas, imágenes o incluso vectores de IA.

La consulta

La forma de pedir información, por ejemplo con SQL: “los usuarios registrados la última semana”.

El SGBD

El software que atiende las peticiones, protege los datos y organiza el almacenamiento.

¿Por qué no usar solo una hoja de cálculo?

Hoja de cálculo

Pensada para que la lean personas. Se vuelve lenta y desordenada cuando miles de usuarios la usan a la vez.

Base de datos

Pensada para que la usen programas. Maneja grandes volúmenes, muchos usuarios simultáneos y reglas de integridad.

Ejemplos cotidianos

  • El saldo de tu cuenta bancaria.
  • El catálogo y los pedidos de una tienda en línea.
  • Las notas y matrículas de una universidad.
  • Los perfiles y publicaciones de una red social.

Sistema gestor de bases de datos

SGBD: el recorrido de una consulta

Un SGBD (en inglés DBMS) es el programa que se sienta entre tu aplicación y los datos guardados en disco. Recibe cada petición, comprueba que sea válida y segura, decide la forma más eficiente de resolverla y devuelve el resultado.

  • PostgreSQL
  • MySQL
  • SQL Server
  • SQLite
  • Oracle
  • MongoDB

Garantías ACID

Los SGBD relacionales protegen cada transacción, por ejemplo una transferencia de dinero, con cuatro propiedades:

AAtomicidadTodo o nada: si falla un paso, se deshace la transferencia completa.
CCoherenciaLos datos siempre cumplen las reglas, como un saldo que no puede quedar negativo.
IAislamientoDos transferencias simultáneas no se mezclan entre sí.
DDurabilidadUna vez confirmada, sobrevive a un corte de energía.

Clasificación

Tipos de bases de datos

Elegir bien depende de la forma de tus datos. Selecciona un tipo para ver cómo guarda la información.

Relacional (SQL)

Guarda los datos en tablas con filas y columnas, y usa relaciones entre tablas mediante claves. Casi todas usan SQL para consultar. PostgreSQL, MySQL o SQL Server son ejemplos; PostgreSQL además admite tipos complejos como JSON.

Ideal para
Datos estructurados con relaciones claras y transacciones que exigen precisión.
Ejemplo
Una tienda que lleva clientes, productos y pedidos en varias sedes; un banco con saldos de cuentas.

No relacional (NoSQL)

Diseñadas para la flexibilidad y la escala. No exigen un esquema rígido: guardan datos como pares clave-valor, documentos, grafos o columnas anchas, ideales para datos no estructurados o semiestructurados.

Ideal para
Datos que cambian rápido, aplicaciones web a gran escala y análisis en tiempo real.
Ejemplo
Una red social que guarda perfiles, publicaciones e interacciones como documentos.

Clave-valor

La forma más sencilla de NoSQL: cada clave única apunta a un valor, como un diccionario. Son muy rápidas porque no recorren tablas para encontrar lo que buscas. Ejemplos: Redis, Memcached.

Ideal para
Búsquedas de alta velocidad, caché, sesiones de usuario y preferencias.
Ejemplo
Una tienda en línea que guarda en caché los detalles de productos para cargar más rápido.

Documentos

Guardan cada registro como un documento JSON o XML, con valores anidados y esquema flexible: dos documentos de la misma colección pueden tener campos distintos. Ejemplos: MongoDB, Firestore.

Ideal para
Gestores de contenido, datos generados por usuarios y modelos que evolucionan.
Ejemplo
Una plataforma de blog que guarda artículos, comentarios y metadatos.

Grafos

Representan los datos como nodos (personas, cuentas, lugares) y aristas (relaciones). Recorren conexiones profundas, como “amigos de amigos”, mucho más rápido que una base relacional. Ejemplo: Neo4j.

Ideal para
Redes sociales, motores de recomendación y detección de fraude.
Ejemplo
Una app de viajes que muestra conexiones entre cuentas, destinos y preferencias.

Series temporales

Optimizadas para guardar y consultar datos con marca de tiempo: métricas, registros o lecturas de sensores. Pueden resumir datos antiguos para ahorrar espacio. Ejemplos: InfluxDB, TimescaleDB.

Ideal para
IoT, monitoreo de rendimiento y seguimiento de datos financieros.
Ejemplo
Una casa inteligente que registra temperatura y consumo de energía a lo largo del día.

Vectorial

Guardan la información como vectores: listas de números que representan el significado. Así encuentran resultados parecidos aunque no compartan palabras: buscar “canino” encuentra “perro”. Son la base de la búsqueda semántica y de muchas apps de IA.

Ideal para
Inteligencia artificial, búsqueda semántica y recomendaciones.
Ejemplo
Recomendar productos según lo que un usuario vio antes.

Orientada a objetos

Guardan los datos como objetos, igual que se representan en lenguajes como Java o Python, con atributos, métodos y herencia. Evitan traducir entre objetos del código y tablas.

Ideal para
Modelos de datos complejos muy integrados con el código.
Ejemplo
Una herramienta de simulación que modela vehículos o edificios del mundo real.

El lenguaje

¿Qué es SQL?

SQL (Structured Query Language, lenguaje de consulta estructurado) es el lenguaje estándar para crear, consultar y modificar datos en bases relacionales.

Es declarativo: describes qué datos quieres y el SGBD decide cómo obtenerlos. Toda base SQL es relacional; casi todas las relacionales usan SQL como interfaz principal.

DDL

Definir la estructura

CREATE ALTER DROP
DML

Manipular los datos

SELECT INSERT UPDATE DELETE
DCL

Controlar permisos

GRANT REVOKE
TCL

Controlar transacciones

BEGIN COMMIT ROLLBACK

Anatomía de una tabla

Una clave foránea es una columna que apunta a la clave primaria de otra tabla; así se crean las relaciones, como inscripciones.estudiante_id → estudiantes.id.

Cómo se maneja SQL

Anatomía de una consulta

5SELECT ciudad, COUNT(*) AS cantidad1FROM estudiantes2WHERE edad >= 183GROUP BY ciudad4HAVING COUNT(*) > 16ORDER BY cantidad DESC7LIMIT 5;

Se escribe empezando por SELECT, pero el SGBD primero busca la tabla (FROM), filtra, agrupa y solo al final elige las columnas. Por eso un alias creado en SELECT no se puede usar en WHERE.

Ejemplos

Las instrucciones esenciales

CREATE TABLE cursos (
  id       INT PRIMARY KEY,
  nombre   VARCHAR(80) NOT NULL,
  creditos INT
);

Crear una tabla

Define el nombre de la tabla, sus columnas, el tipo de dato de cada una y las restricciones: PRIMARY KEY identifica cada fila y NOT NULL obliga a llenar el campo.

Es DDL: cambia la estructura, no los datos.

INSERT INTO estudiantes (id, nombre, ciudad, edad)
VALUES (7, 'Camila', 'Barranquilla', 23);

Agregar filas

Indica la tabla, las columnas y los valores en el mismo orden. Los textos van entre comillas simples; los números, sin comillas.

SELECT nombre, edad
FROM estudiantes
WHERE edad BETWEEN 19 AND 22
ORDER BY edad;

Consultar datos

Devuelve el nombre y la edad de quienes tienen entre 19 y 22 años, de menor a mayor. Otros filtros útiles: =, <>, LIKE 'A%', IN ('Cali','Bogotá'), IS NULL.

UPDATE estudiantes
SET ciudad = 'Cali'
WHERE id = 2;

Modificar datos

Cambia valores de filas existentes. El WHERE es vital: sin él, se modificarían todas las filas de la tabla.

DELETE FROM inscripciones
WHERE nota < 3.0;

Eliminar filas

Borra las filas que cumplen la condición. Igual que con UPDATE, prueba primero la condición con un SELECT para ver qué filas afectarás.

SELECT e.nombre, c.nombre AS curso, i.nota
FROM estudiantes e
JOIN inscripciones i ON e.id = i.estudiante_id
JOIN cursos c ON c.id = i.curso_id
ORDER BY i.nota DESC;

Combinar tablas

JOIN une filas de varias tablas usando sus claves. Aquí cada inscripción se conecta con su estudiante y su curso. e, i y c son alias para escribir menos.

INNER JOIN trae solo coincidencias; LEFT JOIN conserva todas las filas de la tabla izquierda.

SELECT c.nombre,
       COUNT(*)              AS inscritos,
       ROUND(AVG(i.nota), 2) AS promedio,
       MAX(i.nota)           AS mejor
FROM cursos c
JOIN inscripciones i ON c.id = i.curso_id
GROUP BY c.nombre;

Resumir datos

COUNT, SUM, AVG, MIN y MAX calculan un valor por grupo. Combinadas con GROUP BY, responden preguntas como “¿cuál es el promedio de cada curso?”.
