Buenas Prácticas en Diseño de Bases de Datos

Aprende las mejores prácticas para diseñar bases de datos eficientes, escalables y mantenibles. Optimiza el rendimiento y evita problemas comunes con estas técnicas probadas.

Buenas Prácticas en Bases de Datos

Principios fundamentales para un diseño eficiente

Más Tablas - Menos Columnas

6:08 min

Dividir datos en tablas normalizadas en lugar de crear tablas con muchas columnas. Esto mejora el rendimiento y la mantenibilidad.

  • Evita tablas con decenas de columnas
  • Normaliza hasta la 3FN cuando sea posible
  • Separa datos en entidades lógicas

Más Registros - Menos Columnas

5:48 min

Es mejor tener más registros con menos columnas que pocos registros con muchas columnas. Las bases de datos están optimizadas para este patrón.

  • Mejor rendimiento en consultas
  • Índices más eficientes
  • Estructura más flexible

Usar Campos de Estado

5:03 min

Incluir campos de estado (activo, inactivo, pendiente, etc.) en lugar de eliminar registros. Permite auditoría y recuperación de datos.

  • Evita eliminaciones físicas
  • Permite historial y auditoría
  • Facilita reactivación de registros

Uso de Llaves Foráneas

9:35 min

Implementar relaciones con llaves foráneas para mantener la integridad referencial. Define claramente las relaciones entre tablas.

  • Mantiene consistencia de datos
  • Define relaciones explícitas
  • Permite operaciones en cascada

Usar Valores Default

3:25 min

Definir valores por defecto para columnas comunes. Reduce la complejidad del código de aplicación y asegura consistencia.

  • Simplifica inserciones
  • Asegura valores consistentes
  • Reduce código repetitivo

Tablas Resumen

4:15 min

Crear tablas de resumen para datos agregados. Mejora el rendimiento de consultas complejas y reportes frecuentes.

  • Optimiza consultas agregadas
  • Mejora tiempos de reportes
  • Reduce carga en tablas detalle

Ejemplos Prácticos

Aplicación de las buenas prácticas con ejemplos reales

Más Tablas - Menos Columnas

En lugar de crear una tabla "monolítica" con todos los datos, dividimos la información en tablas relacionadas.

MALA PRÁCTICA: Tabla con muchas columnas

Tabla: productos

id nombre descripcion precio categoria subcategoria marca modelo color tamaño peso proveedor telefono_proveedor email_proveedor

BUENA PRÁCTICA: Tablas normalizadas

CREATE TABLE productos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100),
    descripcion TEXT,
    precio DECIMAL(10,2),
    categoria_id INT,
    marca_id INT,
    FOREIGN KEY (categoria_id) REFERENCES categorias(id),
    FOREIGN KEY (marca_id) REFERENCES marcas(id)
);

CREATE TABLE categorias (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(50),
    subcategoria VARCHAR(50)
);

CREATE TABLE marcas (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(50),
    pais_origen VARCHAR(50)
);

CREATE TABLE proveedores (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100),
    telefono VARCHAR(20),
    email VARCHAR(100)
);

Campos de Estado y Valores Default

Implementación de campos de estado para controlar el ciclo de vida de los registros, junto con valores por defecto.

CREATE TABLE clientes (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    telefono VARCHAR(20),
    
    -- Campo de estado con valor por defecto
    estado ENUM('activo', 'inactivo', 'suspendido', 'eliminado') 
           DEFAULT 'activo',
    
    -- Campos de auditoría con valores por defecto
    fecha_creacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    fecha_actualizacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP 
                         ON UPDATE CURRENT_TIMESTAMP,
    creado_por VARCHAR(50) DEFAULT 'sistema'
);

-- En lugar de DELETE, usamos UPDATE para cambiar el estado
UPDATE clientes SET estado = 'eliminado' WHERE id = 123;

-- Consulta solo clientes activos
SELECT * FROM clientes WHERE estado = 'activo';

Tablas Resumen para Reportes

Crear tablas de resumen para datos agregados que se consultan frecuentemente.

-- Tabla de transacciones detalladas
CREATE TABLE ventas (
    id INT PRIMARY KEY AUTO_INCREMENT,
    cliente_id INT,
    producto_id INT,
    cantidad INT,
    precio_unitario DECIMAL(10,2),
    total DECIMAL(10,2),
    fecha DATE,
    FOREIGN KEY (cliente_id) REFERENCES clientes(id),
    FOREIGN KEY (producto_id) REFERENCES productos(id)
);

-- Tabla resumen para reportes diarios
CREATE TABLE resumen_ventas_diarias (
    id INT PRIMARY KEY AUTO_INCREMENT,
    fecha DATE UNIQUE,
    total_ventas DECIMAL(12,2),
    cantidad_transacciones INT,
    promedio_venta DECIMAL(10,2),
    cliente_top INT,
    producto_top INT,
    fecha_actualizacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Procedimiento para actualizar el resumen
CREATE PROCEDURE actualizar_resumen_ventas(IN p_fecha DATE)
BEGIN
    INSERT INTO resumen_ventas_diarias (fecha, total_ventas, cantidad_transacciones, 
                                     promedio_venta, cliente_top, producto_top)
    SELECT
        p_fecha,
        SUM(total),
        COUNT(*),
        AVG(total),
        (
            SELECT cliente_id 
            FROM ventas 
            WHERE fecha = p_fecha 
            GROUP BY cliente_id 
            ORDER BY SUM(total) DESC 
            LIMIT 1
        ),
        (
            SELECT producto_id 
            FROM ventas 
            WHERE fecha = p_fecha 
            GROUP BY producto_id 
            ORDER BY SUM(cantidad) DESC 
            LIMIT 1
        )
    FROM ventas 
    WHERE fecha = p_fecha
    ON DUPLICATE KEY UPDATE
        total_ventas = VALUES(total_ventas),
        cantidad_transacciones = VALUES(cantidad_transacciones),
        promedio_venta = VALUES(promedio_venta),
        cliente_top = VALUES(cliente_top),
        producto_top = VALUES(producto_top),
        fecha_actualizacion = CURRENT_TIMESTAMP;
END;
