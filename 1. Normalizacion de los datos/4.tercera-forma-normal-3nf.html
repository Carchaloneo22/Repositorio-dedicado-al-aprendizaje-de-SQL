¿Qué es la Tercera Forma Normal?

DEFINICIÓN

La Tercera Forma Normal (3NF) es el primer nivel de normalización de bases de datos. Una tabla está en 3NF cuando todos sus atributos contienen valores atómicos (indivisibles) y no hay grupos repetitivos de datos.

Objetivo Principal

La 3NF establece la estructura básica para una base de datos relacional bien organizada. Su objetivo es eliminar:

  • Valores múltiples en una sola celda: Como tener "Rojo, Azul, Verde" en un campo de color
  • Grupos repetitivos: Como tener columnas Teléfono1, Teléfono2, Teléfono3
  • Datos no atómicos: Como almacenar "Nombre: Juan, Apellido: Pérez" en un solo campo
  • Falta de clave primaria: Cada tabla debe tener un identificador único
IMPORTANTE

Atomicidad significa que cada celda debe contener exactamente un solo valor del dominio de datos más simple posible. No puede dividirse más sin perder su significado.

Reglas de la Tercera Forma Normal

Para que una tabla cumpla con 3NF, debe satisfacer las siguientes cuatro reglas fundamentales:

1

Valores Atómicos

Cada columna debe contener valores indivisibles. No se permiten listas, conjuntos o valores múltiples en una sola celda.

-- ❌ Incorrecto Colores: 'Rojo, Azul' -- ✓ Correcto Color: 'Rojo'
2

Sin Grupos Repetitivos

No debe haber columnas repetitivas del mismo tipo de dato (Ej: Tel1, Tel2, Tel3). Cada tipo de dato debe tener su propia tabla si puede repetirse.

-- ❌ Incorrecto Email1, Email2, Email3 -- ✓ Correcto Tabla separada de Emails
3

Clave Primaria

La tabla debe tener una clave primaria que identifique de forma única cada fila. Puede ser simple o compuesta.

PRIMARY KEY (ID) -- o -- PRIMARY KEY (ID1, ID2)
4

Orden Irrelevante

El orden de las filas no debe afectar el significado de los datos. Las filas deben poder reorganizarse sin perder información.

-- Las filas son intercambiables SELECT * FROM tabla ORDER BY columna

Ejemplo 1: Problema de Valores No Atómicos

  • Problemas al actualizar o eliminar datos
  • No se pueden aplicar restricciones de integridad

Ejemplo 3: Problema de Clave Primaria
SIN CLAVE PRIMARIA (Viola 3NF)
Nombre Ciudad Email
Juan Pérez Madrid juan@mail.com
Juan Pérez Madrid juan@mail.com
Ana Silva Barcelona ana@mail.com
PROBLEMAS
  • Filas duplicadas permitidas
  • No hay forma de identificar una fila específica
  • Inconsistencias en los datos
  • Problemas con actualizaciones y eliminaciones
→
CON CLAVE PRIMARIA (Cumple 3NF)
PersonaID ⚡ Nombre Ciudad Email
1 Juan Pérez Madrid juan@mail.com
2 Ana Silva Barcelona ana@mail.com
CREATE TABLE Personas ( PersonaID INT PRIMARY KEY, Nombre VARCHAR(100), Ciudad VARCHAR(50), Email VARCHAR(100) );
BENEFICIOS
  • Cada fila es única e identificable
  • No hay duplicados
  • Integridad referencial garantizada
  • Operaciones precisas y confiables
Ejemplo 4: Problema de Datos Compuestos
DATOS COMPUESTOS (Viola 3NF)

1 García Martínez, María Calle Mayor 15, Madrid, 28001
2 López Silva, Carlos Av. Diagonal 100, Barcelona, 08019
PROBLEMAS
  • Difícil buscar por apellido o nombre
  • Difícil ordenar alfabéticamente
  • No se puede filtrar por ciudad o código postal
  • Formato inconsistente entre filas
→
DATOS ATÓMICOS (Cumple 3NF)

BENEFICIOS
  • Búsquedas precisas por cualquier campo
  • Ordenamiento correcto
  • Filtrado y agrupación eficientes
  • Formato consistente y validable

Proceso Paso a Paso para Aplicar 3NF

Sigue estos pasos sistemáticamente para convertir cualquier tabla a Tercera Forma Normal:

1

Identificar Valores No Atómicos

Revisa cada columna y busca celdas que contengan:

  • Múltiples valores separados por comas o símbolos
  • Listas de elementos
  • Datos que pueden dividirse en partes más pequeñas
-- Ejemplo de valores no atómicos Habilidades: 'Java, Python, SQL' Direccion: 'Calle 123, Ciudad, CP 12345'
2

Separar Valores Múltiples

Para cada columna con valores múltiples:

  • Crear una nueva tabla relacionada
  • Mover los valores múltiples a filas separadas
  • Establecer relación mediante clave foránea
CREATE TABLE Empleado_Habilidades ( EmpleadoID INT, Habilidad VARCHAR(50), PRIMARY KEY (EmpleadoID, Habilidad), FOREIGN KEY (EmpleadoID) REFERENCES Empleados(EmpleadoID) );
3

Eliminar Grupos Repetitivos

Busca columnas con sufijos numéricos (Tel1, Tel2, Email1, Email2):

  • Identificar todas las columnas del mismo tipo
  • Crear tabla separada para estos datos
  • Cada valor va en su propia fila
-- En lugar de: Tel1, Tel2, Tel3 CREATE TABLE Telefonos ( TelefonoID INT PRIMARY KEY, ClienteID INT, Numero VARCHAR(15), Tipo VARCHAR(20), FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID) );
4

Atomizar Datos Compuestos

Divide los campos compuestos en columnas individuales:

  • NombreCompleto → Nombre, Apellido1, Apellido2
  • Dirección → Calle, Ciudad, CodigoPostal
  • FechaHora → Fecha, Hora
-- Separar datos compuestos CREATE TABLE Personas ( PersonaID INT PRIMARY KEY, Nombre VARCHAR(50), PrimerApellido VARCHAR(50), SegundoApellido VARCHAR(50) );
5

Definir Clave Primaria

Asegúrate de que cada tabla tenga una clave primaria:

  • Puede ser un identificador autoincremental (ID)
  • Puede ser una clave natural existente
  • Puede ser una clave compuesta de varias columnas
-- Clave primaria simple ProductoID INT PRIMARY KEY AUTO_INCREMENT -- Clave primaria compuesta PRIMARY KEY (EstudianteID, CursoID)
6

Verificar y Documentar

Verifica que la tabla cumpla con todos los requisitos:

  • ✓ Todos los valores son atómicos
  • ✓ No hay grupos repetitivos
  • ✓ Existe clave primaria
  • ✓ El orden de filas es irrelevante

Documenta las relaciones entre tablas para referencia futura.

CONSEJO

Equilibrio es clave: No todo dato debe atomizarse al extremo. Por ejemplo, "NombreCompleto" podría mantenerse junto si nunca se necesita buscar por nombre o apellido por separado. Analiza los requisitos de tu aplicación antes de decidir el nivel de atomicidad.

Ejercicios Prácticos

1

Biblioteca de Libros

Situación: Tienes la siguiente tabla de una biblioteca:

LibroID Título Autores ISBN Géneros
1 Cien Años de Soledad Gabriel García Márquez 978-0307474728 Ficción, Realismo mágico
2 Good Omens Neil Gaiman, Terry Pratchett 978-0060853983 Fantasía, Comedia

Tarea: Normaliza esta tabla a 3NF. Identifica las violaciones y propón una solución.

Solución:

Violaciones identificadas:

  • Columna "Autores" contiene múltiples valores
  • Columna "Géneros" contiene múltiples valores

Solución Normalizada:

Tabla: Libros
LibroID Título ISBN
1 Cien Años de Soledad 978-0307474728
2 Good Omens 978-0060853983
Tabla: Libro_Autores
LibroID Autor
1 Gabriel García Márquez
2 Neil Gaiman
2 Terry Pratchett
Tabla: Libro_Generos
LibroID Género
1 Ficción
1 Realismo mágico
2 Fantasía
2 Comedia
CREATE TABLE Libros ( LibroID INT PRIMARY KEY, Titulo VARCHAR(200), ISBN VARCHAR(20) ); CREATE TABLE Libro_Autores ( LibroID INT, Autor VARCHAR(100), PRIMARY KEY (LibroID, Autor), FOREIGN KEY (LibroID) REFERENCES Libros(LibroID) ); CREATE TABLE Libro_Generos ( LibroID INT, Genero VARCHAR(50), PRIMARY KEY (LibroID, Genero), FOREIGN KEY (LibroID) REFERENCES Libros(LibroID) );
2

Sistema de Pedidos

Situación: Una tienda online tiene la siguiente tabla de pedidos:

Cliente Dirección Producto1 Cantidad1 Producto2 Cantidad2 Producto3 Cantidad3
Juan López Calle 123, Madrid, 28001 Laptop 1 Mouse 2 NULL NULL
Ana García Av. Principal 45, Barcelona, 08001 Teclado 1 NULL NULL NULL NULL

Tarea: Identifica TODAS las violaciones de 3NF y normaliza completamente la tabla.

Solución:

Violaciones identificadas:

  • No hay clave primaria
  • Grupos repetitivos: Producto1/Cantidad1, Producto2/Cantidad2, Producto3/Cantidad3
  • Columna "Dirección" contiene datos compuestos (Calle, Ciudad, CP)
  • Columna "Cliente" podría separarse en Nombre y Apellido
  • Múltiples valores NULL por límite artificial de productos

Solución Normalizada:

Tabla: Clientes
ClienteID Nombre Apellido Calle Ciudad CodigoPostal
1 Juan López Calle 123 Madrid 28001
2 Ana García Av. Principal 45 Barcelona 08001
Tabla: Pedidos
PedidoID ClienteID FechaPedido
100 1 2025-01-15
101 2 2025-01-16
Tabla: DetallesPedido
DetalleID PedidoID Producto Cantidad
1 100 Laptop 1
2 100 Mouse 2
3 101 Teclado 1
CREATE TABLE Clientes ( ClienteID INT PRIMARY KEY AUTO_INCREMENT, Nombre VARCHAR(50), Apellido VARCHAR(50), Calle VARCHAR(100), Ciudad VARCHAR(50), CodigoPostal VARCHAR(10) ); CREATE TABLE Pedidos ( PedidoID INT PRIMARY KEY AUTO_INCREMENT, ClienteID INT, FechaPedido DATE, FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID) ); CREATE TABLE DetallesPedido ( DetalleID INT PRIMARY KEY AUTO_INCREMENT, PedidoID INT, Producto VARCHAR(100), Cantidad INT, FOREIGN KEY (PedidoID) REFERENCES Pedidos(PedidoID) );
BENEFICIOS
  • Sin límite en número de productos por pedido
  • Sin valores NULL innecesarios
  • Búsquedas eficientes por ciudad, código postal, etc.
  • Estructura flexible y escalable

Registro de Empleados

Situación: Una empresa tiene esta tabla de empleados:

NombreCompleto Departamento Habilidades CertificacionesYFechas
García López, María IT Java, Python, SQL, Docker AWS (2023), Azure (2024)
Martínez Ruiz, Carlos Ventas Negociación, CRM Salesforce (2022)

Tarea: Normaliza esta tabla a 3NF. Presta atención a TODOS los tipos de violaciones.

Solución:

Violaciones identificadas:

  • No hay clave primaria
  • "NombreCompleto" es un dato compuesto (Apellido1, Apellido2, Nombre)
  • "Habilidades" contiene múltiples valores
  • "CertificacionesYFechas" contiene datos compuestos Y múltiples valores

Solución Normalizada:

Tabla: Empleados
EmpleadoID Nombre PrimerApellido SegundoApellido Departamento
1 María García López IT
2 Carlos Martínez Ruiz Ventas
Tabla: Empleado_Habilidades
EmpleadoID Habilidad
1 Java
1 Python
1 SQL
1 Docker
2 Negociación
2 CRM
Tabla: Empleado_Certificaciones
CertificacionID EmpleadoID Certificacion AñoObtencion
1 1 AWS 2023

CREATE TABLE Empleados ( EmpleadoID INT PRIMARY KEY AUTO_INCREMENT, Nombre VARCHAR(50), PrimerApellido VARCHAR(50), SegundoApellido VARCHAR(50), Departamento VARCHAR(50) ); CREATE TABLE Empleado_Habilidades ( EmpleadoID INT, Habilidad VARCHAR(50), PRIMARY KEY (EmpleadoID, Habilidad), FOREIGN KEY (EmpleadoID) REFERENCES Empleados(EmpleadoID) ); CREATE TABLE Empleado_Certificaciones ( CertificacionID INT PRIMARY KEY AUTO_INCREMENT, EmpleadoID INT, Certificacion VARCHAR(100), AñoObtencion INT, FOREIGN KEY (EmpleadoID) REFERENCES Empleados(EmpleadoID) );
PUNTOS CLAVE
  • Los datos compuestos se separaron en campos individuales
  • Los valores múltiples se movieron a tablas relacionadas
  • Las certificaciones incluyen ahora el año como campo separado
  • Estructura permite consultas y análisis flexibles
